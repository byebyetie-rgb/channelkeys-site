How a refresh works

Three steps, every Sunday, with the evidence stored next to the data.

  1. Pull

    Every source file is downloaded from the agency, checksummed and recorded with its URL, size and server timestamp in META_SOURCE_RUN. Unchanged files are reused, not re-downloaded.

    Sundays, 03:40 ET

  2. Join and check

    NDCs are normalized to 11 digits, application numbers to the Orange Book key, labelers to Open Payments manufacturers. Derived fields are recomputed and the new snapshot is diffed against the last one.

    Keys, flags, change log

  3. Publish

    Tables are refreshed in place in Snowflake, so your views and grants keep working. The share is auto-fulfilled to every Snowflake region, usually within a day of first access.

    57 regions, in place

Query it like you already own it

Plain SQL on plain tables. No API, no credits for someone else's compute. The listing ships with validated examples.

-- Marketed packages for a brand, with the exclusivity picture
SELECT ndc11, package_description, start_marketing_date,
       last_patent_expiry, last_exclusivity_date, est_loe_date
FROM core.dim_ndc11
WHERE proprietary_name ILIKE 'eliquis%'
  AND NOT is_discontinued
ORDER BY ndc11;

-- 340B contract pharmacy arrangements added since last week
SELECT entity_key, new_values:pharmacy_name::string AS pharmacy
FROM core.change_log
WHERE table_name = 'opais_contract_pharmacy' AND change_type = 'added';

Questions buyers ask

Write to hello@channelkeys.net for anything not covered.

Isn't this the same data I can download from FDA, CMS and HRSA?

Yes, and that is the point. The sources are public. The work is the parsing, the keys, the joins, the derived fields, the weekly refresh and the change log, which every team otherwise rebuilds and maintains alone. META_SOURCE_RUN lists every agency file behind the current refresh so you can audit the chain.

How current is it?

Refreshed every Sunday morning US Eastern. FDA files change daily and are picked up weekly. Orange Book is monthly, Medicaid SDUD quarterly with restatements, 340B OPAIS daily, Open Payments twice a year. The ledger at the top of this page shows the agency timestamp behind each source.

Does it contain protected health information?

No. Everything comes from public agency files. Personal data is limited to fields the agencies publish, such as covered recipient names in Open Payments and authorizing officials in OPAIS, and we republish only those fields.

How are loss-of-exclusivity dates estimated?

EST_LOE_DATE is the later of the last unexpired, non-delisted patent and the last exclusivity date for the application. It is a planning estimate, not a legal determination; litigation and pediatric extensions change it. Validate before using it in contracts.

Which Snowflake regions and clouds?

All of them. The listing uses cross-cloud auto-fulfillment, so the first time an account in a new region gets the data, Snowflake replicates it there, usually within a day. After that it refreshes with the rest.

Can you add a source or a join we need?

Usually. State Medicaid preferred drug lists, NPPES, CMS Part D spending and FDA shortages are on the roadmap. Enterprise plans get custom tables in a private listing; write to hello@channelkeys.net.
